צנזור אפליקציה — תמונות

העלו APK קיים (למשל אפליקציה שכבר בניתם) כדי לראות את כל קבצי התמונות שבתוכו, ולהחליף או לצנזר (לרוקן) תמונות לא צנועות לפני העלאה לגוגל פליי. הסריקה והעריכה קורות כאן בדפדפן בלבד; ה-APK הערוך נשלח באמצעות ה-GitHub Token והריפו שמולאו למעלה ב"חיבורים" (לא צריך Gemini key לשלב הזה), כדי ש-GitHub Actions ייישר (zipalign) ויחתום (apksigner) אותו מחדש — בלי זה ה-APK לא יתקין, כי כל שינוי בקבצים מבטל את החתימה המקורית. מחיקת תמונה לא מסירה את הקובץ אלא מחליפה אותו בתמונה שקופה ריקה, כדי לא לשבור הפניות למשאב הזה בקוד של האפליקציה.

אמולטור אנדרואיד

העלו כל קובץ APK כדי לראות אותו על מסך טלפון בפרופורציות אנדרואיד, ישר בדפדפן — בלי GitHub ובלי Gemini, הכל קורה מקומית מהקובץ עצמו. אפשר ללחוץ על האייקון כדי "לפתוח" את האפליקציה ולדפדף בין התמונות שנמצאו בתוכה כמו מסכים, ולחזור עם כפתור החזרה. זו לא הרצה אמיתית של האפליקציה — הרצת קוד אנדרואיד אמיתי בדפדפן דורשת אמולטור מלא של מערכת הפעלה (כמו ב-Android Studio) שלא קיים כתשתית קלה כאן; זו תצוגה מקירבת שבנויה מהאייקון והתמונות האמיתיים שנמצאים בקובץ.

תצוגה

הצנרת מייצרת אפליקציית מסך-יחיד עם Activity אחד ואייקון וקטורי, ללא AndroidX וללא XML layouts — זה מה שמאפשר build בלי Gradle. ה-APK נחתם במפתח דיבאג זמני (JAR signing דרך keytool/jarsigner), טוב לבדיקות ולהתקנה ישירה על מכשיר, לא לפרסום בחנות. ה-APK מטאבים "צנזור אפליקציה", "עריכת אפליקציה" ו"תרגום אפליקציה" נחתם בנפרד עם apksigner, באותה שיטה בדיוק כמו הבנייה הרגילה: מפתח דיבאג חדש ואקראי בכל ריצה (לא keystore קבוע). המשמעות: כל APK שיוצא מהכלי הזה — מכל טאב — חתום במפתח שונה מכל APK קודם, כולל קודמים מהכלי הזה עצמו. להתקנה ראשונה זה לא משנה; אבל כדי להתקין גרסה חדשה מעל התקנה קיימת על אותו מכשיר (במקום למחוק ולהתקין מחדש ולאבד נתונים), חובה שיהיה אותו מפתח חתימה — כלומר עדכון-במקום לא יעבוד בין שתי הרצות של הכלי. לפרסום עם עדכונים עתידיים אמיתי (גוגל פליי או התקנה חוזרת על אותו מכשיר) צריך keystore קבוע ולשנות את workflow-י ה-sign כדי שישתמשו בו במקום ביצירת מפתח חדש בכל פעם — תגידו אם תרצו שאבנה את זה.
